How I work

Tools change often. The process changes less: understand the space, frame the decisions, design with precision, and document everything so nothing gets lost at handoff.

Updated July 2026

01

Understand

Map the space before drawing anything. I start with stakeholder context, user research, and competitive analysis — all of it documented and synthesized into maps before a frame is opened.

FigJam Notion
02

Frame

Structure the problem as decisions, not requirements. Journey maps, problem statements, decision criteria — things everyone can align on before pixels exist. I use Claude to pressure-test assumptions and sharpen the framing.

FigJam Notion Claude
03

Design

Component-first in Figma — structure before polish, grids and states before gradients. High-fidelity prototypes when behavior needs to be felt, not just seen.

Figma Protopie Principle
04

Ship

Annotated specs, documented edge cases, handoff notes that leave nothing ambiguous. The work doesn't end at the final mockup — it ends when the engineer can build without questions.
